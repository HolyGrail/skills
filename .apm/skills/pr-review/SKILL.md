## PR Review

Pull Request の体系的レビューでコード品質とアーキテクチャの健全性を確保します。

### 呼び出し例（例示）

```bash
/pr-review 123                      # PR 番号を指定
/pr-review 123 "セキュリティ中心で"    # 観点を絞る
```

PR 情報と会話コメントは `gh pr view <番号> --comments`、行に付いたレビューコメントは `gh api repos/{owner}/{repo}/pulls/<番号>/comments --paginate`、差分は `gh pr diff <番号>` で取る。

### コメント分類体系

```
🔴 critical.must: 致命的問題
├─ セキュリティ脆弱性
├─ データ整合性問題
└─ システム障害リスク

🟡 high.imo: 高優先度改善
├─ 機能不全のリスク
├─ パフォーマンス問題
└─ 保守性の大幅低下

🟢 medium.imo: 中優先度改善
├─ 可読性の向上
├─ コード構造改善
└─ テスト品質向上

🟢 low.nits: 軽微な指摘
├─ スタイル統一
├─ タイポ修正
└─ コメント追加

🔵 info.q: 質問・情報提供
├─ 実装意図の確認
├─ 設計判断の背景
└─ ベストプラクティスの共有
```

### レビュー観点

#### 0. 意図しない削除・データフロー破壊（最優先）

- **削除された機能の確認**: diff で削除された行を全て確認し、その削除が意図的かどうかを検証する
- **データフロー追跡**: 変更された関数の入力→処理→出力を end-to-end で追跡し、既存データが上書き・消失しないことを確認する
- **副作用チェック**: 変更が他の機能に影響を与えないか（特にグローバル状態、キャッシュ、永続化データ）
- **リグレッション**: 既存のテストケースがカバーする機能が壊れていないか

#### 1. コード正確性

- **ロジックエラー**: 境界値、Null チェック、例外処理
- **データ整合性**: 型安全性、バリデーション
- **エラーハンドリング**: 網羅性、適切な処理

#### 2. セキュリティ

- **認証・認可**: 適切なチェック、権限管理
- **入力検証**: SQL インジェクション、XSS 対策
- **機密情報**: ログ出力禁止、暗号化

#### 3. パフォーマンス

- **アルゴリズム**: 時間計算量、メモリ効率
- **データベース**: N+1 クエリ、インデックス最適化
- **リソース**: メモリリーク、キャッシュ活用

#### 4. アーキテクチャ

- **レイヤー分離**: 依存方向、適切な分離
- **結合度**: 疑結合、インターフェース活用
- **SOLID 原則**: 単一責任、開放閉鎖、依存性逆転

### レビューフロー

1. **事前確認**: PR 情報、変更差分、関連 Issue
2. **削除チェック**: diff の削除行を確認し、意図しない機能削除がないかを最初に検証
3. **データフロー追跡**: 変更箇所のデータの流れを追跡し、既存データの上書き・消失がないことを確認
4. **ビルド検証**: プロジェクトの型チェック・ビルドコマンドを実行してエラーがないことを確認
5. **体系的チェック**: セキュリティ → 正確性 → パフォーマンス → アーキテクチャ
6. **建設的フィードバック**: 具体的な改善案とコード例
7. **フォローアップ**（依頼されたとき）: 修正確認、CI 状態。承認や投稿は「注意事項」の「結果の返し方」に従う

### 効果的なコメント例

例示。根拠行と影響範囲を含める。長さは問題の重さに合わせる。

**セキュリティ問題**

```markdown
**critical.must.** `<ファイル>:<行>` でパスワードが平文のまま保存されています

```javascript
// 修正案
const bcrypt = require('bcrypt');
const hashedPassword = await bcrypt.hash(password, 12);
```

DB が漏れると全ユーザーのパスワードがそのまま読めるため、ハッシュ化が必要です。

```

**パフォーマンス改善**
```markdown
**high.imo.** `<ファイル>:<行>` のループ内で N+1 クエリが発生します

```javascript
// 改善案: Eager Loading
const users = await User.findAll({ include: [Post] });
```

現状は一覧の件数に比例してクエリ数が増えます。Eager Loading なら件数によらず一定です。

```

**アーキテクチャ違反**
```markdown
**high.imo.** `<ファイル>:<行>` でレイヤー違反が発生しています

ドメイン層がインフラ層に直接依存しています。
依存性逆転の原則でインターフェースを導入してください。
```

### 注意事項

- **結果の返し方**: レビュー結果はチャットに返す。PR へのコメント投稿はユーザーが明示したときだけ行い、投稿前に本文を見せる
- **建設的トーン**: 攻撃的ではなく協調的なコミュニケーション
- **具体的提案**: 問題の指摘だけでなく解決案を提示
- **優先度付け**: Critical → High → Medium → Low の順で対応
